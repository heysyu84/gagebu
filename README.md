# 가게부 · Money Desk v2

공개 정적 프런트엔드 (개인 금융 데이터는 공개 GitHub에 포함되지 않음)

## 2026-11 리디자인

- `index.html`: 신규 대시보드, 전체 거래, 미분류 검토함, 뱅크샐러드 XLSX 가져오기, 규칙, 백업
- `ledger-v2.js`: 로컬 저장 / v1 장부 복사 / 중복 대조 / 3버튼 분류 / 백업
- `ledger-rules-v2.js`: 토토·투자·수입·충전·내 계좌 송금 제외, 지역·가맹점 분류
- `bank-xlsx-v2.js`: `가계부 내역` 시트가 있는 뱅크샐러드 XLSX 로컬 파서
- `vendor/jszip.min.js`: XLSX 파일의 ZIP 컨테이너 처리 (JSZip, MIT)
- `legacy.html`: 이전 가게부 v1 화면 (기존 `app.js`/`style.css` 활용)

### 주요 정책

- 뱅크샐러드 엑셀은 **사용자 브라우저에서만 처리**하며 파일 전체를 서버에 보내지 않는다.
- 2026년 1월 이후의 **지출**만 후보. 뱅크샐러드의 수입, 토토, 대부분의 이체, 투자, 카드대금 및 상품권 충전은 자동 집계에서 제외.
- 월세·임대료는 `v1` 원본의 해당 기록과 날짜·금액이 맞는 경우만 계좌이체로 링크한다. 수취인명과 금액을 코드에 하드코딩하지 않는다.
- 강동 외 편의점과 식당·카페는 점포 주소가 거래처명으로 충분히 식별될 때만 풍월관으로 분류. 배달 플랫폼 제외.
- 다이소는 풍월관 자동 분류.
- 쿠팡·지마켓·11번가 등 온라인 쇼핑몰은 개인 / 편의점 / 풍월관 **거래별 수동 3버튼 분류**, 거래처 하나에 고정 패턴을 강요하지 않는다.
- 예전 사용자의 가게부는 `localStorage['gagebu-v1-data']`에 그대로 남기고, v2는 `gagebu-v2-private`를 사용한다.
- 기존 현금 매입은 외부 금융 데이터에서 발견되지 않아도 삭제하지 않는다.
- CSV/JSON 내보내기는 사용자의 브라우저에서 다운로드한다.
- 서버 이전은 별도 단계. 아직 Cloudflare D1 실운영/자동 동기화로 표시하면 안 된다.

### 사용자 입력

1. 기존 장부가 있다면 이전 버전의 저장 기록을 자동 복사한다. 다른 기기라면 원본 가게부 JSON을 업로드한다.
2. 뱅크샐러드 XLSX를 선택해 미리보기를 확인한다.
3. 새 거래를 가져온 다음 미분류 검토함에서 분류한다.
4. 설정에서 JSON 백업을 보관한다.

### 빌드

일반 정적 사이트. 별도 빌드 명령 없이 파일을 서빙한다. JSZip 파일은 공식 MIT/GPL 이중 라이선스 배포본을 리포지터리에 포함하고 해당 라이선스 파일도 포함한다.
