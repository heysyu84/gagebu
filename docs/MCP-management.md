# 공통 사이트 관리 MCP

가계부 Worker의 `/mcp`에 배포하는 독립형 MCP 서버입니다. GPT Sites를 호스팅에 사용하지 않으며, 일반 가계부 UI와 데이터 저장 기능은 MCP 없이 계속 동작합니다.

## 최초 연결

1. MCP 주소: `https://store-ledger-private-api.heysyu84.workers.dev/mcp`
2. 인증 방식: **OAuth**, 공개 클라이언트와 동적 클라이언트 등록(DCR), PKCE S256.
3. 로그인 화면에서 기존 가계부 관리자 비밀번호를 입력하고 표시된 권한을 허용합니다.
4. `gagebu:read`는 조회, `gagebu:write`는 거래 수정·환불 관리·변경 취소입니다. 수정 권한은 조회 권한과 함께 요청합니다.
5. 가계부 **저장 · 백업 → AI 관리 연결**에서 활성 연결을 확인하고 권한을 종료할 수 있습니다.

연결 안내: `https://store-ledger-private-api.heysyu84.workers.dev/manage`

ChatGPT에서 **Plugins → ＋ → Add custom MCP server**를 제공하는 환경이라면 위 주소를 등록해 OAuth로 연결합니다. 플러그인 패키지는 `plugins/personal-sites-manager/`에 있습니다. 실제 ChatGPT 연결 완료 여부는 해당 클라이언트에서 설치·인증 후 별도로 검증해야 합니다.

## 효율적인 작업 순서

1. `ledger_find`로 날짜·거래처·금액을 좁혀 필요한 거래만 최대 20건 조회합니다.
2. 결과가 여러 건이거나 사용자의 기억이 불확실하면 대상을 확인합니다. 최신 변경이라고 해서 실수한 변경으로 가정하지 않습니다.
3. `ledger_update_transaction`에 반환된 버전·거래 ID·정확한 날짜/거래처/금액을 전달합니다. 최대 20건을 검증한 뒤 한 번에 저장합니다.
4. 결과의 `verified`와 `changeId`를 확인합니다. 변경 취소는 `ledger_undo`로 해당 변경 필드만 복구합니다.

데이터 수정마다 코드 변경, GitHub 커밋, Actions 실행, 사이트 배포를 하지 않습니다. 코드와 스키마가 바뀔 때만 기존 배포 작업을 실행합니다.

## 기록과 충돌 방지

- 금융 자료를 바꾸는 저장과 `management_changes` 감사 기록은 같은 D1 배치 트랜잭션에서 반영됩니다.
- 버전이 바뀌거나 거래 식별값이 예상과 다르면 저장하지 않습니다.
- 되돌리기는 해당 변경의 필드가 아직 변경 후 값과 일치할 때만 실행합니다. 다른 필드와 다른 거래는 유지합니다.
- 환불은 날짜와 금액을 유지하며, 원결제 연결은 추가 차감하지 않습니다.
- 기존 장부 저장 구조와 브라우저 동기화는 유지합니다. **서버 내부에서는 V2 스냅샷을 읽지만 AI에는 필요한 검색 결과만 반환**합니다. 레코드별 DB 저장으로 전면 이관한 것은 아닙니다.
- 접속 토큰은 1시간, 갱신 연결은 최대 30일입니다. 갱신 토큰을 회전하고 이전 갱신 토큰의 재사용을 차단합니다. 연결을 종료하면 토큰도 사용할 수 없습니다.

## 다른 사이트 추가

현재 `sites_status`에서 가계부만 연결된 것으로 표시합니다. 풍월관·클전은 실제 API, 데이터 형식, 접근 권한이 확인되기 전까지 도구나 자료 접근을 제공하지 않습니다.

같은 MCP 서버에 각 사이트의 어댑터와 별도 범위(예: `windmoon:read`, `windmoon:write`)를 추가할 수 있습니다. 기존 가계부 연결에 새 사이트 권한을 자동으로 부여하지 않습니다.

## 확인

- `npm test`: OAuth·권한·버전·거래 식별·일괄 저장·환불·감사 로그·선택 취소를 합성 자료로 검증합니다.
- `node scripts/check-mcp-live.mjs`: 배포 환경의 기존 비밀 설정으로 임시 조회 전용 연결을 만들고 MCP 호출을 검증한 뒤 폐기합니다. 실제 금융 거래는 수정하지 않습니다.
- 금융 정보·비밀번호·토큰을 GitHub 소스나 로그에 출력하지 않습니다.
